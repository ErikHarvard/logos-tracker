Orientation

What LogOS is

If you are arriving cold, this is the whole project in four paragraphs.

A language, not a syntax

Lingua Adamica is a glyph lambda calculus built on one axiom — ∃(∃) ≡ ∃. A program is a term made of glyphs, and the sign and the thing it denotes are the same object rather than two things joined by convention. Thirty kernel modules are written in it.

A compiler that reproduces itself

The compiler is written in the language it compiles. Given its own source it emits a binary byte-for-byte identical to itself — with no C host and no interpreter anywhere in the loop. That is the axiom holding at the level of the toolchain.

It boots its own metal

Bootloader, interrupts, physical and virtual memory, preemptive tasks, ring-3 user mode, typed inter-process messages, and a sovereign disk image with no GRUB. Eleven bare-metal drivers — keyboard, disk, framebuffer, network card, compositor — are written in the language itself over a thin assembly seam.

Verification is the product

Every claim here is a gate the build actually ran. The governing rule is that a gate that cannot go RED is not a gate: a check must first prove it can fail before anyone is allowed to trust it passing. Most of what slows this project down is that discipline, and it is deliberate.

Self-correction

16 defect classes the system caught in itself

The governing rule is that a gate that cannot go RED is not a gate: every check below had to prove it could fail before its green counted. Each was paid for by a real failure — named precisely, sealed as an executable check, and now run against every script forever at a cost of seconds. Naming a defect prevents nothing. A check is what prevents it.

grep-c-doubling

grep -c prints 0 AND exits 1, so "|| echo 0" appends a SECOND line and a count renders as "0\\n0"

pgrep-self-match

pgrep/pkill -f matches the searching process OWN command line. With pgrep that is a false hit; with PKILL IT IS A SUICIDE -- the shell running the pkill contains the pattern and gets killed mid-script, so everything after the pkill silently never runs. WIDENED 2026-09-09 by METANOE after the narrower pgrep-only form let exactly that through: the pkill killed its own shell (rc 144) before the next line could write a file, and the "did it work?" check self-matched too and reported a script running whose file did not exist. Match a WHOLE ARGV element via /proc/PID/cmdline, or kill by PID

sed-text-as-regex

text interpolated into sed becomes a REGEX; a / or & or backslash in it corrupts the file

tmux-multiword-grep

panes are ~30 cols and the TUI inserts its own line breaks, so a multi-word grep silently returns 0

pipe-masks-exit

a pipeline exits with the LAST command status, so "cmd | head && echo OK" reports OK even when cmd FAILED — I shipped a stale binary this way and nearly drew a conclusion from it

subshell-side-effect

a function called inside $( ) runs in a SUBSHELL, so any variable it sets (ok=0, FAIL=1) is discarded — the caller sees success and the check is silently inert

absence-read-as-status

(cat|head|tail)[^|]*\.(out|log|txt)[\"

hardcoded-kill-code

(rc|RC|status|\$\?)[\"

unlocked-ledger-write

a pattern check — see ~/logos-hexis.sh for the shape it matches

eval-on-path-with-quote

eval on a path breaks on an apostrophe (Erik+quote+sVault) and reports MISSING for a file that exists

send-keys-no-dash-guard

tmux send-keys -l without -- reads a payload beginning with a dash as flags; an answer like "-- use option 2" breaks

unverified-script

every logos-*.sh must survive bash -n

octal-date-arithmetic

bash reads a zero-padded number as OCTAL inside $(( )), so $(date +%M) dies at 08 and 09 with "value too great for base" — and worse, 01-07 silently compute the RIGHT answer, so the bug hides for eight minutes of every ten and then fires. Prefix with 10#

deployed-vs-source-drift

a deployed hook and its source diverge silently: the fix lands on one and not the other

idiom-not-class

COUNTING with an UNANCHORED filename. A sweep searches one FORM, not the CLASS you meant, and a bare filename is a substring: "native_codegen3.la" also matches native_codegen3_hh.la, "organ.la" matches sx6_organ.la, "ata.la" matches kernel/ata.la only if / is a boundary. I reported "36 slow builders" from exactly this and the 36th compiled with a DIFFERENT COMPILER — routing it through the fast path would have built the higher-half kernel wrong and probably still passed. Anchor it: -w, or \b...\b, or a full path. And before reporting any count, state what the pattern MISSES and what it FALSELY MATCHES, and spot-check one of each

pipefail-sigpipe-verdict

a PIPELINE INTO grep -q USED AS A VERDICT, in a file that sets pipefail. grep -q EXITS ON THE FIRST MATCH, SIGPIPEing the writer -- the pipeline then reports 141, a NONZERO status on a SUCCESSFUL match, and the condition reads FALSE when the answer was TRUE. MEASURED 2026-09-09, 5MB, needle at START, and the result depends on WHICH GREP: with newlines kept (cat|grep -q) it is 141 under BOTH GNU grep 3.11 and ugrep 7.8.4 -- a live hazard. Flattened to one line (tr|grep -q) it is 0 under GNU grep, which stops early exit, but 141 under ugrep, which short-circuits mid-line. So the flattened form is SAFE ONLY BY AN UNDECLARED DEPENDENCY ON THE GREP IMPLEMENTATION, and this box has two under one name: interactive grep here is a wrapper dispatching to ugrep, while scripts get GNU grep. That is why this check flags the shape and not the size -- a construct safe by accident is not safe. Fix: a here-string, grep -q PAT <<< "$text", or awk in one pass. (| tee is safe: it never exits early, and ${PIPESTATUS[0]} is the real status.)

The falsifier, and it is checked rather than assumed: if a class already sealed here reappears in shipped tooling, the discipline is not being run — and an unrun guard is exactly the hollow gate this project exists to catch. It happened tonight: HEXIS caught pipefail-sigpipe in a script written an hour earlier, by the same author who sealed the class. That is the mechanism working, not failing.
